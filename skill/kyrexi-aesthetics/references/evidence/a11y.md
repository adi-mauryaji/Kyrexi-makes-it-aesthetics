# Evidence · Accessibility floors (A11Y)

Source for A11Y-001 to A11Y-010: Web Content Accessibility Guidelines (WCAG) 2.2, W3C Recommendation 12 December 2024 (also ISO/IEC 40500:2025) · https://www.w3.org/TR/WCAG22/ · access: OA · reuse: W3C Document License (cite; quote with attribution). Level AA is this skill's floor; one AAA criterion is adopted where noted.

### A11Y-001 · Give text at least 4.5:1 contrast, large text at least 3:1
- grade: A
- applies: all text and images of text (SC 1.4.3, AA)
- not-for: logos, purely decorative text, inactive controls
- value: ratio = (L1 + 0.05) / (L2 + 0.05), L = relative luminance with sRGB threshold 0.04045; large text = at least 18 pt, or 14 pt bold (CSS: 24 px, or 18.67 px bold, since 1 pt = 4/3 px); compare unrounded
- source: WCAG 2.2 SC 1.4.3 and glossary "contrast ratio", "relative luminance", "large scale (text)" · https://www.w3.org/TR/WCAG22/#contrast-minimum · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: the spec gives point sizes, not pixels; the pixel values follow from CSS unit definitions. Text over images needs the worst-case pixel checked. Use `scripts/contrast.py` for palette pairs.

### A11Y-002 · Give UI component boundaries, states and meaningful graphics at least 3:1 against adjacent colours
- grade: A
- applies: input borders, focus indicators, icons that carry meaning, chart elements (SC 1.4.11, AA)
- not-for: inactive components, decorative graphics
- value: ≥ 3:1
- source: WCAG 2.2 SC 1.4.11 · https://www.w3.org/TR/WCAG22/#non-text-contrast · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: pale form borders are the most common failure in minimal designs

### A11Y-003 · Never use colour as the only signal
- grade: A
- applies: links in body text, errors, required fields, states, charts (SC 1.4.1, A)
- not-for: —
- value: add a second cue (underline, icon, text, pattern)
- source: WCAG 2.2 SC 1.4.1 · https://www.w3.org/TR/WCAG22/#use-of-color · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: —

### A11Y-004 · Reflow at 320 CSS px without horizontal scrolling; survive 200% text resize
- grade: A
- applies: every page (SC 1.4.10 and 1.4.4, AA)
- not-for: content that needs two-dimensional layout (maps, data tables, diagrams)
- value: no horizontal scroll at 320 CSS px width; text resizable to 200% without loss of content or function
- source: WCAG 2.2 SC 1.4.10, 1.4.4 · https://www.w3.org/TR/WCAG22/#reflow · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: long words in German, Tamil or URLs break this first; use `overflow-wrap`

### A11Y-005 · Keep layouts working when users increase text spacing
- grade: A
- applies: all text containers (SC 1.4.12, AA)
- not-for: —
- value: no loss of content when line height = 1.5× font size, paragraph spacing = 2×, letter spacing = 0.12×, word spacing = 0.16×
- source: WCAG 2.2 SC 1.4.12 · https://www.w3.org/TR/WCAG22/#text-spacing · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: fixed-height boxes and clipped buttons fail; let containers grow

### A11Y-006 · Make everything keyboard-operable with a visible, unobscured focus indicator
- grade: A
- applies: every interactive element (SC 2.1.1 A, 2.4.7 AA, 2.4.11 AA)
- not-for: —
- value: all functions by keyboard; focus indicator always visible; a focused element is never entirely hidden by author content such as sticky headers or cookie banners
- source: WCAG 2.2 SC 2.1.1, 2.4.7, 2.4.11 · https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: removing `outline` without a replacement is the usual failure

### A11Y-007 · Make pointer targets at least 24×24 CSS px
- grade: A
- applies: buttons, links, form controls, icon buttons (SC 2.5.8, AA)
- not-for: links inside a sentence; targets whose size is set by the line-height of surrounding text; undersized targets whose 24 px circle does not touch another target or its circle
- value: ≥ 24×24 CSS px; 44×44 is a common craft target for touch-heavy and older audiences (craft, not WCAG AA)
- source: WCAG 2.2 SC 2.5.8 · https://www.w3.org/TR/WCAG22/#target-size-minimum · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: default browser inputs are about 21 px tall; set a min-height

### A11Y-008 · Let users stop motion; never flash more than three times a second; honour reduced motion
- grade: A
- applies: carousels, marquees, background video, scroll and hover animation (SC 2.2.2 A, 2.3.1 A, 2.3.3 AAA adopted)
- not-for: essential animation (a progress indicator)
- value: auto-moving content lasting more than 5 seconds needs pause/stop/hide; no more than three flashes in any one second; motion triggered by interaction can be turned off — implement with `prefers-reduced-motion: reduce`, keeping all content visible
- source: WCAG 2.2 SC 2.2.2, 2.3.1, 2.3.3 · https://www.w3.org/TR/WCAG22/#animation-from-interactions · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: 2.3.3 is AAA; this skill adopts it because the media query makes it cheap. Content hidden until a scroll animation runs fails when motion is reduced.

### A11Y-009 · Declare the page language and the language of every passage in another language
- grade: A
- applies: `<html lang>` on every page; `lang` on mixed-language passages, e.g. English terms in a Hindi page (SC 3.1.1 A, 3.1.2 AA)
- not-for: proper names, technical terms, words that have become part of the surrounding language
- value: BCP 47 tags such as `hi`, `mr`, `ta`, `ar`, `ja`, `de`; for right-to-left scripts also set `dir="rtl"` (HTML)
- source: WCAG 2.2 SC 3.1.1, 3.1.2 · https://www.w3.org/TR/WCAG22/#language-of-page · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: `dir` comes from HTML, not WCAG; wrong `lang` also breaks font selection and hyphenation

### A11Y-010 · Expose structure and purpose to assistive technology
- grade: A
- applies: images (1.1.1 A), headings, lists, landmarks, tables (1.3.1 A), page title (2.4.2 A), links (2.4.4 A), form labels (3.3.2 A)
- not-for: —
- value: informative images get text alternatives and decorative ones `alt=""`; one `<h1>` and no skipped levels (craft); a descriptive `<title>`; link text that predicts its target; a visible label for every field
- source: WCAG 2.2 SC 1.1.1, 1.3.1, 2.4.2, 2.4.4, 3.3.2 · https://www.w3.org/TR/WCAG22/ · access: OA · reuse: W3C
- verified: 2026-11-12 standard text
- caveats: native HTML elements before ARIA

### A11Y-011 · Do not treat an automated pass as accessible
- grade: B
- applies: every verify step
- not-for: —
- value: run automated checks, then the manual checklist below
- source: Duran 2017, What we found when we tested tools on the world's least-accessible webpage · GOV.UK accessibility blog (GDS), 24 Feb 2017 · https://accessibility.blog.gov.uk/2017/02/24/what-we-found-when-we-tested-tools-on-the-worlds-least-accessible-webpage/ · access: OA · reuse: OGL v3
- verified: 2026-11-12 full text
- caveats: 143 planted failures, 10 tools; best single tool found 37% (errors and warnings only) or 41% (counting manual-inspection prompts); all tools together 71%; 29% missed by every tool. Tools have improved since 2017, but the gap between automated and manual checking remains the point.

## Manual checklist (no-script path, and after any script)
1. Every text/background pair: compute contrast (A11Y-001), including text over images at its worst spot.
2. Tab through the page: every control reachable, focus always visible and not under sticky elements.
3. Narrow the window to 320 px: no sideways scroll; zoom text to 200%.
4. Turn on reduced motion: nothing essential disappears; nothing loops.
5. Read the headings alone: do they outline the page? Does each link and button say where it goes?
6. Check `lang`/`dir`, `<title>`, alt text and form labels.
